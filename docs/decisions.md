# Decisions, problems found, to-do

The working log of the suite, moved here from the README of `evaluation-bench` (its name inside the minerl repo) on 2026-11-02, unchanged: paths in it are those of that folder (`docs/handoff_cineca_translation.md` is now `docs/translation_handoff.md`, `docs/instructions.md` is `docs/original_spec.md`).

## Decisions taken

1. **Two scorers added** to the five of the instructions: `grid_match` (Zebra's "exact grid match") and `exact_match` (the 20 INVALSI fill-the-gap items).
2. **INVALSI as generated multiple choice**: the paper's own format (every question multiple choice, numeric ones with the authors' distractors `alt1`–`alt3`, fill-the-gap excluded: 400 items), but the model writes its letter instead of being scored by likelihood. Easier than open answers, but diverse, and it removes the ambiguity of numeric questions that ask for part of an answer (e.g. only the exponent). Prompt: our Italian multiple-choice instruction; the paper has no generative prompt.
3. **INVALSI option order**: multiple-choice items keep their options as written in the question; numeric items get their 4 options in a seeded order fixed per item.
4. **GPQA permutation** depends on (seed, record id) only, so it is the same in both languages whatever the row order.
5. **LiveCodeBench window**: `release_v3`, read from the OLMES task definition; the Olmo 3 paper only says "LiveCodeBench v3".
5b. **MT-MATH100 prompt**: the de facto MATH-500 prompt for reasoning models, "Please reason step by step, and put your final answer within \boxed{}.", after the problem.
6. **AIME prompts**: MathArena's instruction (before the problem) for both AIME 2025 and MCLM MT-AIME2024; every AIME answer is an integer in 0–999, which the instruction states.
6b. **AIME 2025 source**: MathArena's copy for English (there is no official machine-readable AIME; MathArena's is curated and verified) and AIME2025-Multilingual's translation of that same text for Italian. MathArena's instruction is used, before the problem, with our Italian translation of it. Earlier sources (`opencompass/AIME2025`, `yentinglin/aime_2025`) were dropped: looser Part II transcription, figures missing.
7. **MBPP+ and HumanEval+ prompt**: EvalPlus's own instruction ("Please provide a self-contained Python script …") with EvalPlus's task prompt in a code block (MBPP+: its docstring with one assert; HumanEval+: signature and docstring), chosen over Olmo 3's, whose cut of the reference solution breaks signatures with type hints and leaks imports. The prompt text comes from EvalPlus's release file: 18 Hub prompts still carry the source URL. The assistant turn is not prefilled.
7b. **GPQA prompt**: Olmo 3's format (OLMES `gpqa::olmo3:adapt`, answer ending "Therefore, the answer is (X)"), chosen over OpenAI simple-evals, which stays one switch away (`TEMPLATE` in `src/loaders/gpqa.py`). Both are described in `reports/gpqa.md`.
8. **Multi-IF checkers**: used as shipped (English sentence model included) except keyword checks, which match whole words in both languages.
9. **Truncated thinking = wrong**, not "score whatever text there is".
9b. **X-AlpacaEval judge**: AlpacaEval 2's setup (`weighted_alpaca_eval_gpt4_turbo`) with a cheaper judge to be chosen instead of its GPT-4 Turbo, its prompt (verbatim in English, translated for Italian runs), preference from the probabilities of the two output ids, seeded random position, length-controlled win rate as headline with the unregularised variant next to it.
9c. **AIW added** (2026-10-15): the 30 prompts of the paper's core tables, not the 826 exploratory ones; Italian built by parsing each English prompt and rendering Italian templates (the parse must rebuild the English exactly); every gold recomputed independently. Reported per subset, prompt type and variation, since the spread across variations is the paper's main signal.
10. **A separate uv project** for this folder, because of the vLLM dependency conflict.
11. **Italian Zebra generated, item-parallel** (2026-10-16), replacing the `multizebra` preview (the generator's published sets: unreviewed Italian, only 2×3 and 4×5, not parallel). The generator's Italian config was reviewed by a native speaker: 2 corrections, 9 naturalness fixes, imperative answer instruction, generic masculine kept (`reports/zebra_it_review.md`; upstream copy kept as `config/zebra/it_case.upstream.yaml`). Puzzles are seeded one by one, the same in both languages, which yields the same puzzle translated clue for clue; value lists follow the config order in both. Sizes: ZebraLogic's 25 (houses 2–6 × categories 2–6), 20 per size (half of ZebraLogic, to save compute on long reasoning), no red herrings. **Seeds 0–999 are reserved for evaluation; training data must use seeds ≥ 1,000,000.** Answer format changed in both languages: the generator's example (`"Bevande_1"` placeholders) made models answer with identifiers (`"Bevande_soda"`) and English values; now keys `casa_X` / `house_X`, the category names as placeholders, and "values written exactly as in the lists above" (Qwen3-8B on 60 small puzzles: 4% → 65% in Italian, 35% → 100% in English; the remaining Italian errors are English values, measured by the off-list rate). Tools are not available to the model: a constraint solver would solve every puzzle.

## Problems found

Nothing below was edited in the data; items are listed in `reports/issues/`.

Sources
- **PolyMath gold answers repaired** (2026-10-15): 8 golds could not be matched even by an identical answer. Repaired, and checked against correct answers in other notations and against wrong ones: `medium-036` (`\right\]` → `\right]`), `medium-111` (missing brace; value checked numerically), `medium-058` (matrix rewritten as `pmatrix`), `top-050`, `top-037`, `top-093` (prose rewritten as sets of values or equations). Partly repaired: `top-088` (matches only the factored form with the letter c). Not repairable: `top-013`. Source golds kept in `meta.gold_original`.
- **PolyMath overlaps the AIME benchmarks**: 28 `high` problems are AIME problems that are also items of `aime25` (14) or `mclm_aime2024` (14). Decision (2026-10-15): they are off by default in PolyMath and scored only in the AIME benchmarks; `meta.also_in` names the twin.
- **MCLM MT-MATH100 has 99 rows**; the paper and the card say 100, and the missing problem cannot be identified. The 99 English problems are MATH-500 verbatim with identical answers.
- **MCLM MT-MATH100 Italian dropped 2 figures**: `mclm-math100-040` (spinning wheel and checkerboard, unsolvable without it) and `062` (shaded region) lost their Asymptote code. **Restored** (2026-10-15) by appending the English Asymptote block, which is code, not language: the only edit to source text in the suite, marked `meta.figure_restored_from_english`, with the original kept in `meta.source_prompt_original`. Minor: in 038 the comments inside the figure code are translated; 057's title pun is rendered literally.
- **MCLM MT-AIME2024**: the torus problem (`mclm-aime2024-028`, AIME 2024 II-08) is broken in both languages. It says the torus rests on the *outside* of the sphere and is *externally* tangent twice, where the original has *inside / internally* for rᵢ, so the gold 127 does not follow. Off by default, not edited. Two problems depend on figures that are not included: 011 (I-06, "as in the examples shown below", still well defined) and 013 (I-08, "arranged in the same manner", as in the original wording). Italian calques and inconsistencies (GPT-4o): "inraggio" for inradius (013, usual term "raggio della circonferenza inscritta"), and "relatively prime" rendered as "relativamente primi", "coprimi" and "primi tra loro". All 30 answers agree with MathArena's copy.
- **X-AlpacaEval**: item *n* is AlpacaEval instruction *n−1* (all 805 checked), so AlpacaEval's English references and per-instruction data apply. One mistranslation, **repaired**: `xalpaca-0031` "How do I detail a car?" had become "Come si curano i dettagli di un'auto?" (car detailing is a deep clean); now "Come si fa pulizia accurata e completa, all'interno e all'esterno, di un'automobile?" (original in `meta.source_prompt_original`). **Length correction, synthetic check**: AlpacaEval 2's standard LC (`length_controlled_v1`) lowers the win rate of outputs that are systematically longer than the reference even when the verdicts ignore length (coin flip: raw 50.9, LC 35.8; model better 80% of the time: raw 75.1, LC 61.1). The cause is its regularisation towards AlpacaEval's English length-gamed baselines; the unregularised variant gives 50.0 and 74.7. Both are reported.
- **HumanEval/32**: the HumanEval+ `test` string on the Hub rejects its own reference solution, so no answer can pass (`_poly(*candidate(*inp), inp)` unpacks the returned float). Excluded from both languages (2026-11-02): `meta.default=false`, filtered in `config/eval.yaml`; the suite scores 163.
- **HumanEval/115**: HumanEval+ ships a corrected English prompt; mHumanEval's Italian was made from the original HumanEval text.
- **mHumanEval-Expert Italian is not usable as the Italian HumanEval**: 40 of 164 items have content problems. 11 docstrings are cut off mid-sentence, about 20 lose a rule or their examples, and in /17, /19, /110, /119, /127 and /141 a value the tests check was translated (`'one'…'nine'` → `'uno'…'nove'`, `"YES"` → `"Sì"`). Several items also have their examples translated into wrong examples. Only 4 are fixable by putting back the English value. About 50 more items have their line breaks collapsed. The text appears to start from mHumanEval's machine translation. Decision (2026-10-15): translate HumanEval+ ourselves; keep mHumanEval-Expert as the reported alternative `humaneval_mhe`.
- **AIME 2025 Italian**: translation style issues in I-10, II-03 and II-12, and "relatively prime" rendered two ways ("relativamente primi" / "primi tra loro"). Meaning is preserved everywhere.
- **INVALSI**: invalsi-mate-271 is broken (no question, context repeated twice; off by default); 074 lists its options without letters and 157 has a distractor equal to the gold (both flagged; off by default since 2026-11-02, not edited: 397 items); 289 has a small typo. The 28 items that mention a figure, table or box were all read: tables are inline and pictures decorative, so all are answerable from the text.
- **Multi-IF**: two Italian prompts (`multiif-3329-6`, `multiif-3329-14`) ask for "inglese semplice", a literal translation of "plain English".
- **Multi-IF sets are not the same task in the two languages**: 6 instruction types exist only in English (case, letter frequency, response language, postscript). On the 492 shared ids the instruction lists are identical.
- **Multi-IF Italian prompts that did not match their checker**: 4 had dropped an instruction the checker still applies (`multiif-1922-5`, `-1922-9`, `-288-9`: "repeat the request first"; `-3245-3`: "no commas, 2 placeholders"), and `-2662-10` asked for 'occuparsi' while the checker tests 'impegna'. **Repaired** (2026-10-15): the 4 instructions restored with our Italian translation of the English sentence, and the keyword aligned. Originals in `meta.source_prompt_original`. Both languages: `multiif-337-3/-15` ask for 400 words but check 336 (lenient, flagged).
- **Multi-IF Italian prompts wrapped in quotes**: 127 of the 493 Italian prompts, and no English one, were wrapped whole in a pair of double quotes (a translation artefact). The prompts read as quoted text, and the "repeat the request" checker can fail if the model repeats the quotes. **Stripped** (2026-10-15): the outer pair only, inner quotes kept; `meta.outer_quotes_removed`, original in `meta.source_prompt_original`. After this, the text every repeat checker expects is present in its prompt (33 Italian, 69 English items checked).
- **Multi-IF keyword checker changed (both languages)**: `keywords:existence` and `keywords:frequency` now match whole words instead of substrings. Before, "use 'il' at most once" counted the 'il' in "possibile", which made `multiif-2716-1/-8` nearly impossible in Italian. It concerns 61 Italian and 137 English instructions, whose scores are no longer identical to Multi-IF's reference code.
- **Multi-IF checkers on Italian**: sentences are counted with the English Punkt model (splits after "sig."), `«…»` is not accepted as quotation, keywords are matched literally (inflected forms fail), elisions add about 1.5% to word counts.
- **GPQA Italian distractor order**: `ellamind/gpqa-multilingual` lists each item's incorrect answers in a random order relative to the English CSV, so the same permutation put different options under the same letter. Fixed with an index-only table (`src/loaders/gpqa_it_distractor_order.json`): 423 items matched by two agreeing automatic methods, 25 by hand. Source text untouched.
- **GPQA source items**: 4 items with duplicated options (in 2 the duplicate is the gold answer, so they cannot be answered reliably), 1 truncated option, 1 typo. The translating model also flagged 39 English items, mostly as having a wrong answer key; these are unverified opinions, not translation problems.
- **ZebraLogic**: the public repo has blank solutions; only the gated one is usable.
- **MultiZebraLogic Italian** is listed upstream as "Preliminary" (not reviewed by a native speaker). Reviewed here (decision 11); the fixes could be contributed upstream.
- **Licences not declared** on the cards of PolyMath, INVALSI and ZebraLogic. Multi-IF, X-AlpacaEval and AIME 2025 (MathArena) are non-commercial.

Environment
- vLLM is capped at 0.8.5 by the CUDA 12.4 driver. That version's `LLM.chat` does not take `chat_template_kwargs`, which is why the harness renders the template itself.
- The GPUs are shared: another user's vLLM job took about 19 GB on both cards during the smoke tests.
- `trace_criteria`'s CLI currently fails on import (`num_pieces` missing from `trace_criteria/io.py`). Not touched here; the run outputs were checked through `trace_criteria.io.load_traces` instead.

Known limits of this code
- The LiveCodeBench driver runs in the same sandbox as the solution: a solution written to forge the result file could pass. Fine for honest model outputs, not a security boundary for scores.
- `mcq` extraction accepts "Risposta: X" / "Answer: X", `\boxed{X}`, or a bare letter. An answer that names the option only in prose is counted wrong.
- `math_verify` requires a `\boxed{}`; an unboxed correct answer is counted wrong.
- HumanEval+/MBPP+ use one wall-clock limit per program (60 s), not EvalPlus's per-task limits calibrated on the reference solution.
